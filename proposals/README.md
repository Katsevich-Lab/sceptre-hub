# Proposals

A proposal records a decision that spans repositories: a new method, a changed
default, a new result column, a public function that exists in more than one
package, or a change to how the project works.

## Process

1. Copy [0000-template.md](0000-template.md) to the next free number with a
   short name, for example `0007-result-schema-v1.md`.
2. Open a pull request with the proposal in status **Draft**. Discussion happens
   on the pull request.
3. The maintainers accept, reject or defer it. The pull request merges with the
   final status either way, so rejected ideas are recorded too.
4. Implementation happens in the component repositories, in issues that link
   back to the proposal.

A later proposal can supersede an earlier one; both then say so.
