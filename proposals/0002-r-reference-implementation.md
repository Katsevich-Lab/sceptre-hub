# 0002: The R package as the reference implementation

- **Status:** Accepted
- **Author:** Eugene Katsevich
- **Date:** 2026-10-26
- **Affects:** all

## Motivation

SCEPTRE has independent R and Python implementations, plus a Nextflow pipeline
that runs them. They need a way to show that they compute the same thing,
without maintaining a prose specification of the methods that would duplicate
the code and go out of date.

## Proposal

- The R package is the reference implementation for the statistical methods.
- Agreement is defined by the [parity contract](../contracts/parity.md): small
  fixtures generated by R, a reference stability test in R, and comparison
  tests with stated tolerances in pysceptre and the pipeline.
- Contracts are executable where possible and cover only boundaries between
  repositories. The methods are specified by the papers and the book, not
  restated in this repository.
- A deliberate divergence from R needs its own accepted proposal and tolerance
  tier.

## Alternatives considered

- **A written specification of the methods,** implemented by both packages.
  Rejected: it would be about as large as the code and hard to keep current.
- **A shared native core used by both packages.** It would remove most parity
  work, but it is a large architectural change. Deferred; see the roadmap's
  "Later" list.

## Validation

The R reference stability test and the pysceptre comparison tests run in each
repository's CI. Full-scale agreement on real data is checked periodically
with the validation scripts in this repository.

## Implementation

1. R: add the parity fixtures, the generator script and the reference stability
   test.
2. pysceptre: vendor the fixtures with a sync script, add the tolerances file
   and the comparison tests.
3. Pipeline: run the fixtures end to end and compare.

## Decision

Accepted by Eugene Katsevich on 2026-10-26. Open for review by the other
maintainers.
