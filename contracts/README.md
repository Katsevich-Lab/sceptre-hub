# Contracts

Contracts are the few things the SCEPTRE implementations must agree on. They
cover only the boundaries between repositories, never internals.

## Principles

- **The R package is the reference implementation** for the statistical
  methods ([proposal 0002](../proposals/0002-r-reference-implementation.md)).
  Other implementations show agreement by reproducing R's outputs.
- **Executable, not prose.** Whatever a test can check is a test or a
  machine-readable file. Prose explains intent and tolerances only.
- **Changes go through a proposal,** together with the matching test or fixture
  change. There are no prose-only edits.
- **The methods themselves** are specified by the published papers and the
  [book](https://timothy-barry.github.io/sceptre-book/). They are not
  restated here.

## Contracts

| Contract | Form | Where it is enforced | Status |
| --- | --- | --- | --- |
| [Parity](parity.md) | Fixtures generated by R, plus a tolerances file | R: reference stability test. pysceptre and the pipeline: comparison tests. | Agreed; fixtures not yet built |
| Result schema | A machine-readable schema (columns, types, allowed values) with a version number | Each package's CI validates its output against it | Not started |
| Data-model mapping | A short table of how `SingleCellExperiment` and AnnData/MuData objects correspond, plus round-trip tests | Package tests | Not started |
| [File formats](../file-format/) | A specification (`SPEC.md`) with machine-readable definitions in `spec/`, validators in R and Python, and a conformance set | The validators, and the conformance set run in both languages | Draft 0.1, not accepted |
| Compatibility | A table of which package versions support which fixture and schema versions | Updated as part of each release checklist | Not started |
